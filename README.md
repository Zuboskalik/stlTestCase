# Распределение стоимости рейсов

Отчёт о выполнении тестового задания по расчёту стоимости рейсов сборных грузов и пересчёту счетов.

За октябрь 2026 обновлено 6 счетов. Итог по новому расчёту составил **454 610,80 р**. [Таблица с экрана после применения](#результат-пересчёта-за-октябрь-2026) приведена ниже.

## Запуск

Нужен PHP 8.2+ с расширением `pdo_sqlite`. Браузер загружает jQuery с `code.jquery.com`.

При первом запуске из корня репозитория выполните:

```bash
php bin/reset-db.php
php -S localhost:8000 -t public
```

Откройте [http://localhost:8000](http://localhost:8000/).

Запуск через Docker с инициализацией базы, если файла ещё нет:

```bash
docker run --rm -it -p 8000:8000 -v "${PWD}:/app" -w /app php:8.4-cli sh -c "if [ ! -f data/app.sqlite ]; then php bin/reset-db.php || exit 1; fi; php -S 0.0.0.0:8000 -t public"
```

`php bin/reset-db.php` пересоздаёт базу `data/app.sqlite` из исходных данных. При повторном запуске с существующей базой достаточно команды запуска PHP-сервера. Обновление кода работает с прежней схемой SQLite.

## Выполнение функциональных требований

| Пункт ТЗ | Результат |
|---|---|
| 1. Расчёт долей рейса | Стоимость распределяется пропорционально суммарному объёму грузов клиента. Сумма начислений по рейсу с грузами совпадает со стоимостью рейса до копейки. На одних и тех же данных расчёт даёт одинаковый результат. |
| 2. API долей рейса | `GET /api/trip_split.php?trip_id=11` возвращает распределение по клиентам. Для отсутствующего рейса возвращается HTTP 404. |
| 3. Распределение стоимости в карточке рейса | Таблица на jQuery получает из API число грузов, вес, объём, долю в процентах и сумму для каждого клиента. Внизу показаны сумма по клиентам и стоимость рейса. |
| 4. API счетов за месяц | Предпросмотр показывает текущие и новые суммы без записи в SQLite. Применение создаёт недостающие счета и пересчитывает существующие в одной транзакции. Повторный вызов на тех же данных оставляет записи без изменений. |
| 5. Экран "Счета за месяц" | Страница доступна из меню. По кнопке "Показать" выводятся суммы до и после пересчёта, разница и итоги. Кнопка "Применить" запрашивает подтверждение, затем выводит результат по каждому клиенту. |
| 6. Пересчёт за октябрь 2026 | Пересчёт применён через экран. Обновлены 6 существующих счетов. Таблица с результатом приведена ниже. |

Оставшиеся после округления вниз копейки получают клиенты с наибольшими дробными остатками. При равенстве приоритет у меньшего ID клиента. В счета включаются рейсы по дате отправления, отменённые рейсы исключаются. При пересчёте сохраняются статусы счетов и даты отправки и выгрузки. Отчёт "Загрузка машин" показывает доли по весу. Формат CSV для 1С сохранён.

## Правила для неполных данных

- Отсутствующий объём отдельного груза считается нулём. Если общий объём рейса нулевой, стоимость распределяется по весу. Если и общий вес нулевой, стоимость делится поровну между клиентами рейса. Рейс без грузов не даёт начислений. Основание расчёта указано в поле `basis`.
- Если у существующего счёта за выбранный период больше нет подходящих рейсов, после пересчёта его сумма равна нулю, а строки очищаются.

## API

| Метод | Адрес или данные | Результат |
|---|---|---|
| GET | `/api/trip_split.php?trip_id=11` | Распределение по клиентам. Для отсутствующего рейса возвращается 404 |
| GET | `/api/billing_preview.php?period=2026-10` | План пересчёта без записи в базу |
| POST | `/api/billing_apply.php`, поле формы `period=2026-10` | Созданные, обновлённые и неизменившиеся счета, суммы до и после |

Денежные значения в JSON передаются строками с двумя десятичными знаками и точкой. Поле `share` содержит долю от 0 до 1.

## Что проверено

- Проверены синтаксис PHP и JavaScript, распределение копеек, отсутствующие объёмы, пустые и отменённые рейсы, создание счетов, откат при ошибке и повторное применение.
- В headless Playwright проверены карточка рейса и экран пересчёта на 1440x900 и 375x812, загрузка API, отмена подтверждения и применение октября.

## Что не сделано

- Отправка счетов клиентам и повторная выгрузка уже выгруженных счетов в рамках пересчёта не реализованы. Импорт файла в 1С не проверялся.
- Локальная база с применённым пересчётом исключена из Git. Начальные данные содержат суммы до пересчёта.
